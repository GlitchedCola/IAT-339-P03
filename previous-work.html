Process Analysis 1

This is a top-down shooter game. This is a solo project for IAT 167: Digital Games: Genre, Structure, Programming and Play, where the objective was to create a basic shooter. While the core gameplay (e.g. shooting enemies while moving around to avoid touching them) was predetermined, I designed extra features such as power-ups, multiple waves, and different enemy types. I made the game in JavaScript on p5.js.

One challenge that I encountered was that I had to find a way to make the game difficult in a way that was not lazy/relied on cheap solutions (e.g. spawning a bunch of basic enemies, giving the boss a large amount of health) and that would be fun for the player. My solution to do this was to implement different enemy types which would begin to spawn as the player progressed through the game.

Another problem I faced was that when I gave certain enemies the ability to shoot projectiles, their projectiles would hit other enemies and damage them. In order to solve this, I separated their projectiles into a separate subclass and made it so that only player projectiles damage enemies.

Through this project, I gained experience designing shooter games, a genre that I had experience with as a player but not as a designer. I also learned how to add difficulty to a game while also providing a fun experience for the player. In terms of game development, I gained experience developing games with JavaScript and troubleshooting bugs/poorly-implemented features.

Process Analysis 2

This is a platformer game. It was a solo project for IAT 167: Digital Games: Genre, Structure, Programming and Play. The objective of this project was to create a platformer game. The only requirement was that the game needed to be a platformer, so the core gameplay (moving around the map to rescue NPCs and collect treasures) was my own design. I also designed the additional gameplay concepts (e.g. constantly respawning enemies, platforms that are only usable after using a specific power-up). In terms of development, I made a UML diagram to map out the classes I needed to implement, and I made the game in JavaScript on p5.js.

The main challenge with this project was having to adjust the complexity/scope of the gameplay. While p5.js is easy to work with and the programs made with it can run on any browser, eliminating the need for downloads, it is not very powerful, making it difficult to add more complex features (e.g. multiple levels). In order to solve this, I had to adapt my original game concept to fit the capabilities of p5.js. This meant having to go from multiple levels to a single level and adding respawning enemies to maintain the difficulty.

In terms of game design, I learned how to design platformer games and add multi-state elements (e.g. unlockable platforms). In terms of game development, I learned how to implement collision when working with sprites, which do not always have conventional shapes.
